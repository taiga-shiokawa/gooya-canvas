# テンプレートの抽象化 と Node Reference 要件

前作業 `.steering/20260908-workflow-templates/` の修正依頼。第 2 弾（残り 7 パターン）は不要と確定した。

## 背景

第 1 弾のテンプレートは実案件の手順をそのまま写したため 14〜21 ノードあり、
「作り始めるきっかけ」ではなく「完成済みの実装手順書」になっていた。
ノード数を減らして抽象度を上げ、利用者が自分の業務に合わせて肉付けする余地を残す。

あわせて、各ノード種別の意味・使いどころを引ける公式リファレンスを用意する。
テンプレートから具体的な記述を削る分、ノード種別そのものの理解を支える場所が必要になる。

## 機能要件

| # | 要件 | 出典 |
|---|---|---|
| AB-1 | テンプレート 4 本のノード数を 8〜9 個へ減らす（現状 14〜21 個） | 修正依頼 |
| AB-2 | ノードの title / description を抽象的な表現にする。特定サービス名・API 名・実装手順を書かない | 修正依頼 |
| AB-3 | 各テンプレートに「決めておくこと」を 1 つの Note ノードとして残す。実装手順ではなく判断の観点を書く | 修正依頼 |
| AB-4 | 既存サンプル `Interview Evaluation Reminder` は変更しない（Reference Workflow であり E2E が名称に依存する） | §7.6 / e2e |
| RF-1 | Header の Edit の隣に `Reference` を追加し、各ノード種別の解説を読めるようにする | 修正依頼 |
| RF-2 | 11 種すべてを解説する。種別ごとに 概要 / 使いどころ / 接続ルール / config キーの意味 を載せる | FR-001 / §3.3 |
| RF-3 | Flow Review が欠落を警告する config キー（RV-W02〜W05）を「必須」として示す | §10.2 |
| RF-4 | Canvas / Palette と同じアイコンとアクセント色で示し、画面上のノードと対応が取れること | — |
| RF-5 | 接続ルール（Trigger は入力なし / End は出力なし / Note は接続不可 / 自己接続禁止 / Cycle は許可）を載せる | FR-007 / §5.2 |

## 非機能要件

| # | 要件 | 出典 |
|---|---|---|
| AB-5 | 抽象化後も全テンプレートが Flow Review で ERROR / WARNING / INFO すべて 0 件であること | 前作業 TP-10 |
| AB-6 | テンプレート JSON に特定サービスの実 URL を含めない | NFR-001 / NFR-002 |
| RF-6 | リファレンスの内容はノード種別のドメイン知識なので `workflow/domain` が所有する。表示だけを presentation が行う | architecture §3.2 |
| RF-7 | 解説対象の網羅性（11 種すべて）と config キーの一致（`NODE_CONFIG_KEYS`）をテストで機械的に担保する | development-guidelines §5.1 |
| RF-8 | 新モジュールを追加しない（8 モジュール固定） | repository-structure §2 |

## 受け入れ確認（実機）

- File > New from Template から各テンプレートを読み込むと 8〜9 ノードで表示される
- 各テンプレートで Flow Review が 0 Errors / 0 Warnings / 0 Suggestions
- 各テンプレートで Generate Prompt が成立する
- Header の Edit の隣の `Reference` から 11 種の解説が読める
- リファレンスのアイコン・色が Palette と一致している
- 必須の config キーに印が付いている
- E2E の主要導線に退行がない
